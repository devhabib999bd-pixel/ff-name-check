Developer Documentation

Verify a Free Fire player UID from your website or app and get the nickname and region.

Quick start

  1. Ask the admin for an API key (looks like ffk_...).
  2. Call the endpoint from your server (PHP, Node, Python). Never put the key in browser JavaScript or an Android app.
  3. Check status in the JSON and act on it (table below).
curl "{{ base }}/api/v1/check?uid=8412833300" -H "X-API-Key: YOUR_KEY"

Endpoints

MethodPathPurpose
GET / POST/api/v1/checkVerify a UID. Parameter uid (query, form or JSON body).
GET/api/v1/healthService status. No key needed.

Authentication

Send the key in the X-API-Key header (preferred) or as ?key=. Keys are limited per minute; the admin sets the limit per key.

Parameters

uid: numeric Free Fire player ID, 5 to 15 digits.

Response

{
  "ok": true,
  "status": "success",
  "data": {
    "nickname": "PlayerName",
    "region": "BD",
    "open_id": "dc7900db52e712c4470786d6132c5b85",
    "img_url": "https://cdn-gop.garenanow.com/..."
  },
  "cached": false,
  "message": ""
}

status values

statusHTTPMeaningWhat your app should do
success200Player exists. data is filled.Accept. Show nickname, optionally save it.
invalid_id200No player with this UID.Ask the user to re-enter the UID.
unverified200Checker is down; admin enabled fallback. data is null.Accept the UID but mark it "unverified" for manual review.
unavailable503Checker is down and fallback is off.Show "try again later" or queue the request.
rate_limited429Too many requests for this key.Wait (see Retry-After header), then retry.
bad_request400UID is not 5 to 15 digits.Validate input before calling.
unauthorized401Key missing, wrong or disabled.Contact the admin.

Code examples

PHP

function ff_check($uid) {
    $ch = curl_init("{{ base }}/api/v1/check?uid=" . urlencode($uid));
    curl_setopt_array($ch, [
        CURLOPT_RETURNTRANSFER => true,
        CURLOPT_HTTPHEADER => ["X-API-Key: YOUR_KEY"],
        CURLOPT_TIMEOUT => 20,
    ]);
    $body = curl_exec($ch);
    curl_close($ch);
    return json_decode($body, true) ?: ["status" => "unavailable"];
}

$r = ff_check($_POST['uid']);
switch ($r['status']) {
    case 'success':     $name = $r['data']['nickname']; /* save user */ break;
    case 'invalid_id':  /* tell user the UID is wrong */ break;
    case 'unverified':  /* accept, flag for manual review */ break;
    default:            /* unavailable / rate_limited: try later */ break;
}

Node.js

const res = await fetch("{{ base }}/api/v1/check?uid=" + uid, {
  headers: { "X-API-Key": process.env.FF_KEY },
});
const r = await res.json();
if (r.status === "success") console.log(r.data.nickname);

Python

import requests
r = requests.get("{{ base }}/api/v1/check", params={"uid": uid},
                 headers={"X-API-Key": KEY}, timeout=20).json()
print(r["status"], r.get("data"))

Android (Kotlin, OkHttp), call your own backend, not this API directly

Your app calls your PHP/Laravel server, and your server calls this API with the key. Putting the key inside an APK lets anyone extract it.

Best practices

  • Verify once, store the result. Check the UID at registration or tournament join, then keep the nickname in your database. Do not call on every page load.
  • Results are cached for a few minutes by the panel, so repeating the same UID is cheap.
  • Always handle unverified and unavailable. The source is an unofficial endpoint protected by bot checks and can pause without warning while the admin refreshes the cookie.
  • Do not run bulk loops. Sending thousands of UIDs at once will get the shared cookie blocked for every site using this service.
  • Set a timeout of about 20 seconds on your side.
