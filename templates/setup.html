Setup guide

Install, deploy, and keep the cookie fresh.

A. Get a fresh cookie (do this whenever the dashboard says "Expired")

  1. In Chrome on a PC, open shop.garena.my, choose Free Fire. If you are logged in, press Logout first.
  2. Press F12 → Network tab → tick Keep log → type player_id_login in the filter.
  3. Enter a Player ID and press Login. Solve the captcha if it appears.
  4. Click the player_id_login row → Headers → scroll to Request Headers.
  5. Right-click the cookie value → Copy value. Do the same for user-agent.
  6. Paste into Settings (cookie box and User-Agent box), save, then run one UID in the Tester.

Shortcut: if only the cookie expired and the browser is the same, paste just the datadome value into "Quick update".

B. Run on Windows (testing)

  1. Install Python 3.12 (tick "Add python.exe to PATH").
  2. Extract the project folder, copy .env.example to .env, and set ADMIN_USER and ADMIN_PASS.
  3. Double-click run_windows.bat and open http://127.0.0.1:5000/admin.

C. Deploy on a VPS (CyberPanel / OpenLiteSpeed)

  1. In CyberPanel create a website for a subdomain such as ffapi.yourdomain.com and issue SSL.
  2. Upload and extract the project to /opt/ffpanel, then run: 
    cd /opt/ffpanel
python3 -m venv venv && ./venv/bin/pip install -r requirements.txt
cp .env.example .env && nano .env      # set ADMIN_USER / ADMIN_PASS
cp ffpanel.service /etc/systemd/system/
systemctl daemon-reload && systemctl enable --now ffpanel
  3. CyberPanel → Websites → your site → vHost Conf, paste, save, restart OpenLiteSpeed: 
    extprocessor ffpanel {
  type                    proxy
  address                 127.0.0.1:5000
  maxConns                100
  initTimeout             60
  retryTimeout            0
  respBuffer              0
}
context / {
  type                    proxy
  handler                 ffpanel
  addDefaultCharset       off
}
  4. Open https://ffapi.yourdomain.com/admin, sign in, change the password, then add the cookie.
The datadome cookie is tied to the network and browser it came from. If the VPS gets captchas while your PC works, the cookie must come from a browser on the same IP as the server, or the server needs a proxy that matches the browser.

D. Connect your websites

  1. API Keys → create one key per site (for example "Game Sports BD").
  2. Give the site's developer the key and the Developer Docs link. The base URL is {{ base }}.
  3. Watch usage in Logs. Disable a key instantly if it is abused.

E. What happens when Garena blocks the cookie

  • After the configured number of captchas in a row the panel marks the cookie Expired, pauses calls to Garena for the cooldown period, and sends a Telegram alert (if set up).
  • With fallback off, your sites receive unavailable. With fallback allow, they receive unverified and can keep taking registrations.
  • You paste a fresh cookie (section A). The pause is cleared automatically on save.

F. Security checklist

  • Change the default admin password on first login.
  • Serve over HTTPS only. The panel stores your Garena cookie in data/panel.db; restrict that file (chmod 600) and back it up.
  • Never commit .env or data/ to Git.
  • Use a separate API key per website and keep rate limits low.
